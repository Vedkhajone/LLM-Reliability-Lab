3. PART 2: PROJECT ARCHITECTURE
======================================================================
Data flow:
  1. datasets/generated/*.jsonl are loaded and validated.
  2. Each experiment turns cases into prompts (build_items).
  3. ExperimentRunner plans, rate-limits, retries and sends requests, appending
     each response to results/raw/<experiment>__<model>.jsonl (append-only).
  4. score_raw applies each experiment's rubric, writes
     results/processed/scored.* and a human review queue.
  5. compute_metrics + paired tests produce metrics.csv, comparisons.csv,
     figures and report.md.
  6. The dashboard and the paper-template filler read those outputs.

File map:
  src/reliability_lab/models/       Claude, OpenAI, Gemini, local HF, mock;
                                    shared retry, rate limit, timeout, token and
                                    cost tracking
  src/reliability_lab/experiments/  Six modules, each with a documented rubric

                                    failure categories

5. THE SIX EXPERIMENTS
======================================================================
1 Instruction conflicts - Does the model notice/handle contradictions?
  Conditions: direct, format, length, priority, ambiguous, order-swapped pairs,
  satisfiable controls.
  Metrics: conflict recognition, instruction adherence, constraint violation,
  appropriate resolution, over-flagging, order sensitivity.

2 Misleading context - Can false context override correct knowledge?
  Conditions: correct, incorrect, contradictory, irrelevant, partial,
  fabricated-authority.
  Metrics: factual accuracy, misleading susceptibility (by provenance), context
  influence, unsupported assertion.

3 Uncertainty - Does it abstain when the answer cannot be established?
  Conditions: fictional papers/people, unverifiable, missing input, ambiguous,
  insufficient evidence, answerable controls.
  Metrics: appropriate abstention, hallucination, false abstention, non-epistemic
  refusal, ECE, Brier.

4 Adversarial - How often do benign injections displace the task?
  Conditions: override, role-play, quoted, retrieved document, formatting,
  multi-step, no-attack control.
  Metrics: attack success (strict), canary leak (lenient), task preservation,
  constraint violation.

5 Context sensitivity - Does extra context help or hurt?
  Conditions: C0 none, C1 relevant, C2 irrelevant, C3 misleading, C4 excessive,
  C5 contradictory.
  Metrics: accuracy by condition, degradation vs C0, context benefit,
  sensitivity score.

6 Response stability - Are answers invariant to wording, format, order, sampling?
  Conditions: original, 2 paraphrases, structured format, reversed context,
  repeats.
  Metrics: answer agreement, semantic consistency, outcome variance, wording
  sensitivity.

Design choices:
- Exp 1 pre-registers acceptable outcomes per case; not every resolution counts.
- Exp 3 separates epistemic abstention from bare refusal.
- Exp 4 uses only benign canary tokens; no harmful content.
- Exp 6 reports factual agreement separately from stylistic similarity.

6. EVALUATION AND STATISTICS
======================================================================
A. Deterministic (default): normalised word-boundary ground-truth matching,
   structural validators (JSON, bullets, tables, counts), canary detection.
B. Semantic: sentence-embedding similarity for stability (falls back to word
   overlap if unavailable; backend is recorded).
C. Human: rows flagged needs_review go to review_queue.csv; labels in
   results/human_labels.jsonl are merged; agreement (raw, Cohen's kappa) is
   reported.
LLM judge (optional, off): extra signal only; refuses to judge a model's own
outputs.

Statistics: Wilson intervals; cluster bootstrap over cases for repeated
measures; exact McNemar with Holm correction for paired models; Cohen's h, odds
ratio, paired accuracy difference; ECE and Brier; Cohen's kappa. Non-significance
is never treated as equivalence.

9. DESIGN CONCERNS AND LIMITATIONS
======================================================================
With ~20 cases per experiment only large effects are detectable. Nothing here
supports claims about model internals or overall safety.

- Dataset: model-generated, unreviewed; ground truths unchecked; fictional
  entities may coincide with real ones; a Claude author may favour Claude models.
- Ceiling effects and contamination: famous facts are likely memorised.
- Heuristic scoring: English-phrase detectors need human validation.
- Single prompt templates; neutral context instruction measures default
  behaviour only.
- Sampling control differs by provider: where temperature/seed is not accepted,
  Exp 6 measures provider-default variance, confounding cross-model comparisons.
  Check params_applied.
- Context confounds: C4 differs from C1 in length and distractors.
- Multiplicity: only the primary metric per experiment is confirmatory.
- Model versions drift: record exact ids and run dates; do not pool across dates.
- Literature list written from memory without lookup: verify every reference.
